# RPGツクール5 — マップ編集・テストプレイのカメラ

対象は日本版 **SLPS-20143 / BB78C51D**。マップ編集ではカーソル、テストプレイでは操作キャラを中心に、原作のカメラを回す。最終行列を書き換える方式ではない。実装は [Orbit・場面判定・復帰](../../../adapters/rpgmaker5/adapter.py) と [水平FOV](../../../adapters/rpgmaker5/lens.py) に分かれる。画角・移動・復帰の実測はこの2場面、ステートの内訳は編集4件とテストプレイ3件。全マップや他のエディター画面での動作を示すものではない（[実測結果](TEST_RESULTS.md)）。

| 操作 | 対応範囲 |
|---|---|
| Orbit | yawは全周、GUIの仰角は水平から20〜75°、距離は200〜1600（ゲーム単位）。注視点は原作に従う |
| 水平FOV | Orbit中のみ20〜60°。OriginalでのFOV単独変更は非対応 |
| 非対応 | Free Camera、視点・注視点の独立オフセット、注視点の高さ調整 |

**原作のR1カメラ操作を使うときは先にOriginalに戻す。** 入力を遮断するパッチはなく、原作が同じパラメータを変更した場合は、Orbitの値を押し付けない。

## 書込み対象の特定

EEアドレス `0x70C178` から始まるタスク登録表は、1枠につき先頭・末尾ポインタ各1語。原作はタスクの `+0x3C` の16ビットIDから枠を選んで登録し（`0x32980C` 以降）、解放時は該当する先頭・末尾を更新する（`0x329DD4` 以降）。同じポインタが残っていた `0x5CA348` や、カメラらしい数値を持つヒープ領域だけを入口にはしない。

| 活動中であることを確認する枠 | 確認内容 |
|---|---|
| 77: `0x70C3E0` / `0x70C3E4` | 両端がマップタスク `0x11458C0`。自己参照 `+8`、ID `+0x3C`、3つのコールバック `+0x2C/+0x30/+0x34` を照合。先頭語がカメラ構造体（rig）`0x1145900` を指し、`rig+4` は `0x16A770` |
| 3: `0x70C190` / `0x70C194` | 両端が同じ描画タスク。EE RAM内の整列したアドレス、親 `+4` が上記マップタスク、`+8` が自己参照、`+0x2C` が描画関数 `0x11D950` |

7ステートで特定したマップタスクとrigの配置に限定する。別の配置へ再割当てされた場合に探索して書くことはしない。両枠が成立した上で `rig+0x68` が **0なら編集、3ならテストプレイ**。1、2、未知値は対象外。`0x16A438` は1〜3を同系統の処理に送るため、関数アドレスだけではテストプレイと区別できない。高さや距離の値も場面IDではない。

## Orbitと追従

描画タスク `0x11D950` は原作の注視点を組み立て、`0x11DBDC` から `0x11D598(注視点, 距離, 極角, yaw)` を呼ぶ。Orbitが変更するデータは次の符号付き32ビット整数3語だけ。WORLD `0x6BC3B0`・VIEW `0x6BC3F0`、カーソル座標、キャラ座標、移動入力は書かない。

| rigからの位置 | 描画での意味 | GUIとの関係 |
|---|---|---|
| `+0x08` | 水平方位 yaw。`0x10000`で1周 | GUIのyawと符号が逆。書込みは原作と同じ `(-32768, 32768]` に折り返す |
| `+0x14` | 注視点から視点までの距離 | 整数のゲーム単位。原作の近・中・遠の目標値は350 / 1000 / 1600 |
| `+0x20` | 鉛直からの極角。`0x4000` が45° | GUIの仰角は**水平から**なので `90° − 極角`。極角の1度は `65536/180` 単位で、yawと換算係数が異なる |

静止時の注視点XYは、`rig+0x60/+0x64` のタイル番号から各軸 `16 × タイル番号 + 8`。描画座標のZは編集時0、テストプレイ時は `−(符号付き高さ)`。共通カメラには描画座標 `(X, Z, Y)` の順で渡す。`rig+0x738` が非ゼロのときは通常のタイル移動中にも使われる `+0x810/+0x814/+0x818` の補間位置を参照する。描画側はXYだけを整数に変換し（`0x11DA34/44`）、高さは浮動小数のまま使う。このフラグが立っただけでOrbitを解除しない。移動処理 `0x115898` 付近は入力角とrigのyawを足して8方向へ量子化する。画面が連続回転しても歩行が任意方位になるという意味ではない。

### ステートから独立に照合した値

編集4件（`base1` 系）とテストプレイ3件（`base2` 系）を比較。WORLDの第3行を前方ベクトル、第4行を視点として、`視点 + 距離 × 前方` から注視点を逆算した。表は丸めた描画座標。待機のみの2件は各基準と同じ行列・3語だった。

| 条件 | yaw / 極角（raw） | 距離 | 逆算した注視点 (X,Y,Z) |
|---|---|---:|---|
| 編集・基準 | `0 / 0x4400` | 1000 | (1816, 1848, 0) |
| 編集・カメラのみ変更 | `0x2000 / 0x6000` | 1000 | (1816, 1848, 0) |
| 編集・カメラとカーソル変更 | `0x8000 / 0x2000` | 1000 | (1752, 1784, 0) |
| テストプレイ・基準 | `0x8000 / 0x4000` | 350 | (1752, 1784, −32) |
| テストプレイ・キャラとカメラ変更 | `−0x2000 / 0x4000` | 350 | (1768, 1800, −32) |

## 水平FOV

距離やWORLDの変更で画角を代用しない。`0x11D6E0` の1命令が投影に渡す焦点距離を選び、後続の処理が水平投影スケール `sx = 2 × 焦点距離` を生成する。幅512基準なので、実画角は `2 × atan(256 / sx)`。原作は焦点距離512、`sx=1024`、水平約28.07°。設定では逆算した `128 / tan(希望水平FOV / 2)` を1命令で表現できる最寄りの値に丸める。このため設定60°と読戻し約59.93°は矛盾しない。読戻すのはGUIの設定値ではなく `0x6BC4E0` の描画側スケール。

この1命令だけはデータでなくコードの変更。続く3命令が原作と一致し、対象語が原作値か、同じ接続世代に自分で書いた値でなければ変更しない。解除では所有する命令だけを原作に戻す。未所有の命令は希望値と同じでも引き取らない。

## 復帰と限界

- 開始時に接続世代・場面・描画タスクと3語の生値を記録する。原作のyaw更新カウンタ `+0x10`、距離・極角の連動カウンタ `+0x18`、関連フラグ `+0x28` が非ゼロなら取得しない。原作の更新関数 `0x126568` / `0x126670` はこれらの角度や距離を自身で進める。ステップ量やカウンタの退避・書戻しはしない。
- 適用・通常解除ともに、書く前に活動タスク・場面と3語すべての期待値を照合する。解除時も条件が一致したときだけ取得時の3語に戻す。不一致なら古い値を新しい場面へ移植しない。競合後はOriginalに戻してからOrbitを選び直す。
- ホストの読取り・書込みはEEに対する不可分な処理ではない。同じ接続・同じアドレス・同じ値を再現するステートロードまで識別できる保証はない。ステートを切り替える前にOriginalへ戻すのが確実。所有不明のFOV命令が残った場合は強制上書きせず、未改変ステートまたは再起動を使う。
- 対象は上記タスクとモードを確認できる場面。7ステートは全マップ、作品データ、イベント、メニュー、長時間動作や、操作範囲の全組合せでの描画・地形との干渉を保証しない。
