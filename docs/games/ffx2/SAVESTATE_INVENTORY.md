## 3. 情景（スクリーンショットによる判定）

いずれも **カシル（飛空艇）船内の通常フィールド**。ユウナが操作可能。

| # | 画面の内容 | カメラ | キャラクタ |
|---|---|---|---|
| S0 `base` | 船内デッキ。ユウナを背後やや上方から捉える標準構図 | 基準 | 基準位置 |
| S1 `base_only_wait` | S0 とほぼ同一。照明・群衆アニメのみ微差 | ほぼ同一（静止） | ほぼ同一（待機） |
| S2 `base_left_moved` | ユウナが画面左へ移動。カメラはほぼ据え置き | 0.03 単位しか動かない | **左へ移動** |
| S3 `base_chara_little_moved_and_cam_big_moved` | 通路の奥から手前を見る構図。ユウナが遠方に小さく映る | **大移動（Z +170）** | わずかに前進 |

この4点で「時間経過のみ」「キャラのみ移動」「カメラ大移動」の3要因を分離できる。

## 4. 実測した差分（EE RAM 32 MiB）

`numpy` によるバイト単位比較。S1 をノイズ基準とした。

| 比較 | 変化バイト数 | 変化領域数 |
|---|---|---|
| S0 vs S1（時間経過のみ＝ノイズ） | 645,585 | — |
| S0 vs S2 ∪ S0 vs S3 から S1 分を除外（シグナル） | 524,513 | 3,966 |

**ノイズ床が大きい**ため「変化したアドレスを全部見る」方式は使えない。
そこで本解析では次の3段階のふるいを使った。

1. **ビット一致フィルタ** — S0 と S1 で *ビット単位で同一* の float のみ残す
   （待機中に動く値＝アニメ・タイマ・入力・一時バッファを除去）
2. **変化署名** — S3 で大きく変化し S2 でほとんど変化しない値を「カメラ候補」、
   逆を「プレイヤー候補」として分類
3. **実画面スイープ** — 候補を 400 Hz で実際に書き換え、PCSX2 の描画ウィンドウを
   取得してピクセル差分がノイズ床（`frac_gt16 < 0.015`）を超えるものだけを採用

## 5. カメラ／プレイヤー値の対応（4ステート）

`eye` = レンダーカメラ位置、`target` = 注視点、`scale` = 投影スケール。

| 値 | S0 base | S1 only_wait | S2 left_moved | S3 cam_big_moved |
|---|---|---|---|---|
| eye.x (`0x340360`) | -1.3086 | -1.3086 | 1.6140 | 12.8997 |
| eye.y | -26.0506 | -26.0506 | -26.0680 | -23.2309 |
| eye.z | 131.9051 | 131.9051 | 131.9160 | 301.6991 |
| target.x (`0x340380`) | -0.7377 | -0.7377 | 4.1490 | -0.9720 |
| target.y | -7.2519 | -7.2519 | -7.2520 | -11.2520 |
| target.z | 110.2479 | 110.2479 | 110.3120 | 133.0080 |
| player anchor (`0x3312D0`) x | -0.7377 | -0.7377 | 4.1490 | -0.9720 |
| player anchor z | 110.2479 | 110.2479 | 110.3120 | 133.0080 |
| 投影スケール (`0x340B00`) | 619.0 | 619.0 | 619.0 | 724.0 |

**読み取れること**

* `target.x/z` は `player anchor.x/z` と完全一致する。注視点はプレイヤー基準点を追う。
* `eye` は S2（キャラのみ移動）で x が +2.92 しか動かず、S3（カメラ移動）で z が +169.8 動く。
  → eye はカメラ、anchor はプレイヤーとして分離できている。
* 投影スケールは S3 のみ 619 → 724 に変化。これは FOV が変わったことを意味する
  （`docs/games/ffx2/FOV_ANALYSIS.md` 参照）。

  `pcsx2\fork-B056de99\sstates\SLPS-25250 (8A6D7F14).20..23.p2s` に**複製**して
  スロット経由でロードした（元ファイルは不変）。

* 復元検証: `tools/verify_state.py` で S3 をロード後、5か所の値が展開データと
  1e-3 以内で一致することを確認済み（E2E-02 の証拠）。
