# FFX-2 アダプターの技術メモ（旧 README §1・§6・§11 を移設）

FF10-2（`SLPS-25250` / CRC `8A6D7F14`）のカメラ制御の実装メモです。README から移した内容を、
2026-11-02 の高さ基準・メインカメラ限定の注視点フックに合わせて更新しています。
見出し番号と過去の測定値は元の記録を残し、現行仕様と区別します。
解析の経緯・今回の測定詳細は [メモリマップ](<CAMERA_MEMORY_MAP.md>)・
[Orbit 解析](<ORBIT_BREAKTHROUGH.md>)・[歩行方向調査](<WALK_DIRECTION_INVESTIGATION.md>) を参照してください。

## 旧 §1 できること（FFX-2）

> **現行のパッチ所有権**: 外部 `.pnach` や `EnableCheats` は不要です。runtime が Orbit / Free Camera で
> 視線・stock-camera フックを適用し、Original / 通常終了で stock に戻します。
> GUI の「ゲームパッチ」欄でモードに応じた状態を確認してください。未知の命令は強制上書きしません。
> 旧版の外部カメラパッチは無効化してください（§6.2.1・§11）。

ゲームは eye と注視点を毎フレーム書き戻すため、それらを外部から直接上書きし続ける方式では競合します。
本 MOD は、eye にはゲーム自身の加算フィールド `0x3403E0` の**オフセット**を使い、
注視点にはメインカメラ限定のフックで未使用スロット `0x33FC40` を渡し、この競合を避けます。

従来の差分注入方式の保持試験では、35 秒で書込み 1 回、連続フレーム差分 mean 0.50〜0.56 / frac>40 0.002
（静止時ノイズ以下）を測定しました。これは当時の保持条件での値であり、現行 runtime 全体の書込み回数を
示すものではありません。stock-camera フック使用中の歩行先更新などは別途書込みます。

## 旧 §6 実装上の制約（重要）

### 6.1 視線の実体は `normalize(注視点 − 視点)`

描画用の向きは look-at 行列ビルダ `FUN_001b07a0` が引数の視点・注視点・up から組み立てます。
この関数はメインカメラ以外からも呼ばれるため、現在は以下のロード命令を stock のまま保ちます。

```
0x1B07F8  lqc2 $vf4, 0x00($s2)   ; 視点引数
0x1B07FC  lqc2 $vf5, 0x00($s1)   ; 注視点引数（命令 DA250000 を維持）
0x1B0800  lqc2 $vf8, 0x00($s0)   ; up 引数
```

通常のメイン描画は eye `0x340360`・target `0x33FC10`・up `0x33FBC0 = (0,-1,0)` を渡します。
MOD は §6.2.1 の呼出側フックで、対象が一致したときだけ target を `0x33FC40` に切り替えます。
実測で `normalize(注視点 − 視点)` は描画基底 `0x53ADA0` と小数5桁まで一致しました。

`0x53AD80`（基底）・`0x33F620`（ビュー行列）・`0x3403B0`（yaw/pitch）はすべて
**出力のミラー**で、書いても描画は変わりません。これが以前「回らない」原因でした。

### 6.2 競合を無くす（ちらつき対策）

ゲームは視点 `0x340360` と注視点 `0x33FC10` を**毎フレーム書き戻します**
（外部から書いた値は 50 ms 以内に消える）。毎フレーム上書きし続ける方式では、
レンダラがゲーム値を読むフレームが混ざってちらつきます（実測: 連続フレーム差分 mean 46.4）。

本 MOD は競合を「勝つ」のではなく「無くします」。

| 対象 | 方法 |
|---|---|
| 視点 | ゲームが毎フレーム計算する `0x340360 = 0x340370 + 0x3403E0` の**加算項にオフセットを書く**。ゲーム自身が毎フレーム再現するので競合しない |
| 注視点 | メインカメラの呼出側だけをコードケーブへ向け、出力・eye・target が一致した場合のみ `0x33FC10` → 未使用スロット `0x33FC40` へ変更。ゲームはこの照準スロットを上書きしない |

視点オフセット・照準の値は、値の変化やゲーム側での上書きを検出したときに再公開します。
上記の保持測定と、フック使用中の歩行先更新などを含む runtime 全体の書込み頻度は区別してください。

### 6.2.1 パッチの所有権とメインカメラ限定フック

現行実装は [adapter.py](<../../../adapters/ffx2/adapter.py>) と
[lookat_cave.py](<../../../adapters/ffx2/lookat_cave.py>) が管理します。

- `0x1AE0F0` の `jal` を `0x80000` の 60-byte コードケーブへ向け、元の delay slot は維持します。
  出力 `a0=0x33F620`・eye `a1=0x340360`・target `a2=0x33FC10` がすべて一致するときだけ
  `a2 += 0x30` とし、共通ビルダーへ戻ります。他の呼出し・補助カメラの引数は変更しません。
- 共通命令 `0x1B07FC` は `DA250000`（stock）に維持します。旧版の `DA250030` はすべての呼出しで
  target+0x30 を読むため、ミニマップや別の一時注視点まで壊していました。既知の旧値は stock へ移行します。
- runtime が Orbit / Free Camera で視線フックと stock-camera フックを適用し、Original / 通常終了で
  呼出箇所を stock に戻します。到達しなくなったコードケーブの命令自体は残ります。
  GUI の手動パッチ操作はそのモード内だけの上書きで、モード変更時に解除されます。
- ステート読込後は約 1 秒ごとに状態を確認して再適用します。適用前に命令・delay slot・コードケーブを確認し、
  未知の命令や使用中の領域は命令を書き換える前に拒否します（その前にスロットの初期化書込みはあり得ます）。
  強制終了では復元処理を実行できません。
- 外部 `.pnach` と `EnableCheats` は不要です。旧外部定義を再適用すると runtime の移行・復元と競合します。
  旧定義を無効化してゲームを再起動するのが確実です。PCSX2 のパッチ再読込で続行する場合は、
  外部再適用を止めたうえで Original に切り替え、既知命令が復元されたことを確認してください。
  定義の無効化・再読込だけで既に書かれた命令が stock に戻るとは限りません。

2026-11-02 は、ルカの対象場面で旧共通パッチとの A/B、および yaw 0/±90/180°・FOV 80°・Free Camera における
ミニマップ位置の安定を確認しました。投影補正だけを外しても旧パッチのずれは残り、メイン限定フックで解消しました。
全ルカマップ・イベント・戦闘・長時間を網羅した確認ではありません。詳細は [メモリマップ](<CAMERA_MEMORY_MAP.md>)。

### 6.2.2 回転中心

回転中心は**キャラクター基準点 `0x3312D0` に固定の Y 補正 `+5.0` を加えた点**、
注視点も同じ点（+ `look_height` + 注視点オフセット）です。
`0x340380` はゲームのカメラ追従点で、演出カメラに応じてキャラクターとの高さ差が変わるため、
Orbit の基準には使いません。固定 `+5.0` は通常フィールドの従来の基準・保存設定との互換用です。
`look_height` は既定 `-6.0`（+Y が下向きなので補正後の基準点より 6 単位上、
キャラクター基準点に対しては Y `-1.0`）。キャラクター自身の高低差には追従します。
ロード中のゼロ近傍の基準点には補正を加えず、既存のシーンガードを維持します。
2026-11-02 のルカ 20 秒往復では、カメラ追従点の相対 Y が `+10 → +3 → +10` と変わっても
注視点のキャラクター相対 Y は `-1` を維持しました。これは演出切替中の高さ・移動確認であり、
従来の歩行方向角度測定（0.3 秒）を長時間検証へ拡張したものではありません。

### 6.3 シーン判定

`is_field_like()` が以下を満たさない場合は書き込みを停止します。

* プレイヤー基準点が (0,0,0) でない（ロード中でない）
* 視点-注視点距離が 1〜2000
* 視点-プレイヤー距離が 400 以下

カメラ切り替え（カットイン・エリア移動）ではゲーム本来の視点がプレイヤーから約 170 単位離れます。
旧しきい値（120）ではここで書き込みが止まり、ユウナが中央に来ませんでした。
現在は、オービットの視点を毎回プレイヤー基準で置くため、ゲーム側の視点は「妥当な値か」だけを見ます。
（`base_chara_little_moved_and_cam_big_moved.p2s` で確認。ユウナは画面中央に来ます）

これは座標の妥当性を見るヒューリスティックな安全弁です。戦闘・イベント・メニューを網羅して識別するものではなく、
それら全場面での安全な自動無効化を保証する確認は未実施です。

書き込み中は約 10 ms ごとに視点オフセット `0x3403E0` と照準スロット `0x33FC40` を読み戻します。
ゲームに上書きされていれば（場面切り替えや動画の後など）、次フレームに再書き込みします
（`RuntimeStats.resyncs` で回数を確認できます）。

### 6.5 既知の制限（フック無効時）: 歩行方向はカメラに追従しない（B-08）

※ 現行 runtime は §11 のフック方式も一緒に適用します。以下は旧方式で stock-camera フックを使わず、
視点オフセットと注視点差し替えだけを使った場合の記録です。現行の追加設定手順ではありません。

ゲームの歩行は、MOD が動かしている描画カメラ（`0x3403E0`・`0x33FC40`）ではなく、
ゲーム本来のカメラ状態から方向を決めています。そのため、オービットで視点を回しても
左スティックの進行方向は変わりません。書き込み実験の詳細は
[`WALK_DIRECTION_INVESTIGATION.md`](WALK_DIRECTION_INVESTIGATION.md) を参照してください。

### 6.4 壁抜け

Orbit は球面上にカメラを置くため、狭い通路で 180° 回すとカメラが壁や天井の
内側に入り、床や壁で画面が埋まることがあります。ゲーム側のカメラ衝突判定を
経由しないため避けられません。距離を短くするか Pitch を下げてください。

## 旧 §11 ゲーム本体のカメラを使う方式（フック、既定で有効）

オービットの視点・中心・歩行の向きを、ゲーム本体のカメラルーチンに任せる方式です。
runtime がゲームの視点計算（`FUN_001B0388`）の入力を MOD 専用スロットへ向けます。
旧方式の [pnach テンプレート](<../../../patches/stock_camera_hook.pnach.txt>) は解析・移行用の資料で、
現行の有効化手順ではありません。以下の方向角度は従来の短時間測定です。

- 視点の角度・距離・中心（ユウナ）が指定どおりになることを確認済み（軌道 0/90/180°、距離 28.7、
  ユウナは床・エリア切り替え・左寄りの 3 場面で中央）。
- **歩行方向も軌道に追従**: 軌道 0° で直進（進行方向 −0.2°）、軌道 +90° で −90.2°、−90° で +89.8°
  （いずれも歩き始めの 0.3 秒の実測。その後は壁で止まるため、広い場所での長い歩行は未確認）。

### 有効・無効（現行 runtime）

GUI で Orbit / Free Camera にすると自動適用し、Original / 通常終了で stock に復元します。
毎回の手動 `disable` は不要です。パッチ管理の導入経緯は
[歩行方向調査 §12.7](<WALK_DIRECTION_INVESTIGATION.md>) を参照。
現行のメインカメラ限定フックは本書 §6.2.1 が正です。

旧版の外部 stock-hook ブロックが残っている場合だけ、次を使います。

```powershell
python tools/stock_hook.py status
python tools/stock_hook.py disable
```

[stock_hook.py](<../../../tools/stock_hook.py>) の `enable` は廃止済みです。`status` は旧 hook の
`001A9604` 行を検出し、`disable` は旧 stock-hook 見出し以降を除去します。
旧 look-at 行 `001B07FC / DA250030` の検出・除去は行わないため、残っていれば別途無効化してください。
変更後は §6.2.1 の再起動、または外部再適用停止・パッチ再読込・Original での復元確認を行います。

### 注意

フックは runtime のスロット更新を前提とします。通常終了では解除しますが、強制終了した場合や
外部パッチが再適用された場合は古いスロットを読み続け得ます。その場合は外部定義を無効化して再起動してください。
再接続後に未知のコード状態が表示されたときは、強制上書きせず原因を確認します。

### 演出エリアの FOV: 過去の制限と確認範囲

- [歩行方向調査 §11](<WALK_DIRECTION_INVESTIGATION.md>) の測定当時は、
  `other_area_base` で `0x340B00` を変えても画像が変わりませんでした。
- 後の [投影元の変更と検証（§12.6）](<WALK_DIRECTION_INVESTIGATION.md>) では、
  同ステートの FOV 変更が画像に反映されることを確認しています。今回のルカ対象場面でも FOV 80° と
  ミニマップの位置安定を確認しました。ただし、別エリア・別描画経路を含む FOV の一般保証ではありません。
  全ルカマップ・イベント・戦闘・長時間は未網羅です。
